# 安卓插件

## 创建插件

插件名称：默认情况下，创建的插件名称为，`tauri-plugin-名称` 格式，插件所在的文件夹名称也是这种格式

### 直接创建

在任何地方都可以创建

找个文件夹，执行命令：

~~~cmd
npx @tauri-apps/cli plugin new 名称 --android
~~~

执行命令的目录下生成`tauri-plugin-名称` 名称的插件项目

### 在tauri项目中创建

必须得在tauri应用项目中创建

在项目根目录下，执行命令：

~~~cmd
npm run tauri plugin new 名称 --android
或
yarn tauri plugin new 名称 --android
或
pnpm tauri plugin new 名称 --android
或
cargo tauri plugin new 名称 --android
~~~

在项目根目录中生成`tauri-plugin-名称` 名称的插件项目

#### error.rs（错误类型）

作用：定义插件自己的错误枚举 `Error` 和 `Result<T>` 别名。这样命令返回 `Result<T>` 时，出错信息能序列化成字符串传回前端，而不是直接 panic。

~~~rust
use serde::{ser::Serializer, Serialize};

pub type Result<T> = std::result::Result<T, Error>;

#[derive(Debug, thiserror::Error)]
pub enum Error {
  #[error(transparent)]
  Io(#[from] std::io::Error),
  #[cfg(mobile)]
  #[error(transparent)]
  PluginInvoke(#[from] tauri::plugin::mobile::PluginInvokeError),
}

impl Serialize for Error {
  fn serialize<S>(&self, serializer: S) -> std::result::Result<S::Ok, S::Error>
  where
    S: Serializer,
  {
    serializer.serialize_str(self.to_string().as_ref())
  }
}

~~~

#### commands.rs（前端命令）

作用：定义可供前端调用的功能

~~~rust
// 引入 Tauri 的核心类型：AppHandle（应用句柄）和 Runtime（运行时抽象）
use tauri::{AppHandle, Runtime};

// 引入同 crate 下的模型模块中定义的数据结构
use crate::models::*;
// 引入为 AppHandle 扩展的 notification_settings() 方法
use crate::NotificationSettingsExt;
// 引入本 crate 的 Result 类型别名
use crate::Result;

/// 定义一个 Tauri 命令：打开通知设置页面
/// #[tauri::command] 宏将其注册为可被前端通过 invoke 调用的命令
#[tauri::command]
// async 表示该命令为异步执行，避免阻塞主线程
// R: Runtime 是泛型参数，表示兼容所有 Tauri 运行时（如 Wry）
pub(crate) async fn open_notification_settings<R: Runtime>(
    // AppHandle 是应用级别的句柄，可用于访问插件状态和管理资源
    app: AppHandle<R>,
    // 请求参数，下划线前缀表示当前未使用但保留接口一致性
    _payload: OpenNotificationSettingsRequest,
) -> Result<OpenNotificationSettingsResponse> {
    // 通过扩展 trait 获取 NotificationSettings 实例并调用 Android 原生方法
    app.notification_settings().open_notification_settings()?;
    // 构造成功响应并返回给前端
    // kotlin不返回任何数据
    Ok(())
    
}
~~~

#### mobile.rs（移动端专属）

作用：用于桥接Android / iOS原生代码

~~~rust
// 引入 serde 的反序列化 trait，用于解析配置参数
use serde::de::DeserializeOwned;
// 引入 Tauri 插件 API 相关类型
use tauri::{
    // PluginApi 用于注册原生插件，PluginHandle 用于持有插件句柄
    plugin::{PluginApi, PluginHandle},
    // AppHandle 是应用句柄，Runtime 是运行时泛型参数
    AppHandle, Runtime,
};

// 引入同 crate 下的模型模块
use crate::models::*;

// Android 插件标识符常量
// 此字符串必须与 Android 端 Kotlin 文件的包名一致
// 在 Tauri v2 最新版中，Android 不需要 android_plugin_binding! 宏
// 只有 iOS 才需要 ios_plugin_binding! 宏进行绑定
const PLUGIN_IDENTIFIER: &str = "com.plugin.app_setting";

/// 初始化移动端插件实现
/// 此函数在插件 setup 阶段被调用
pub fn init<R: Runtime, C: DeserializeOwned>(
    // 应用句柄，当前未使用但保留参数位置
    _app: &AppHandle<R>,
    // Tauri 提供的插件 API，用于注册 Android 原生插件
    api: PluginApi<R, C>,
) -> crate::Result<NotificationSettings<R>> {
    // 注册 Android 原生插件
    // 第一个参数是插件标识符（即 Kotlin 文件的包名）
    // 第二个参数是 Kotlin 插件类的类名
    let handle = api.register_android_plugin(PLUGIN_IDENTIFIER, "AppSettingPlugin")?;
    // 使用注册成功的句柄构造 NotificationSettings 并返回
    Ok(NotificationSettings(handle))
}

/// 移动端 API 访问句柄
/// 包装 PluginHandle，提供类型安全的方法调用
pub struct NotificationSettings<R: Runtime>(PluginHandle<R>);

// 为 NotificationSettings 实现业务方法
impl<R: Runtime> NotificationSettings<R> {
    /// 调用 Android 原生方法打开通知设置页面
    pub fn open_notification_settings(
        &self,
    ) -> crate::Result<()> {
        // 通过 PluginHandle 运行移动端插件命令
        // 第一个参数是 Kotlin 端 @Command 注解的方法名（驼峰命名）
        // 第二个参数是传递给原生方法的请求体
        self.0
            .run_mobile_plugin("openNotificationSettings", OpenNotificationSettingsRequest {})
            // map_err(Into::into) 要求 crate::Error 实现了 From<PluginInvokeError>
            // 这在 lib.rs 的 Error 枚举中通过 PluginInvoke 变体实现
            .map_err(Into::into)
    }
}
~~~

#### desktop.rs（桌面端专属）

作用：编写桌面端插件所需的功能，开发移动端插件时也需要，只不过没有功能

~~~rust
// 引入 serde 的反序列化 trait
use serde::de::DeserializeOwned;
// 引入 Tauri 插件 API 和应用句柄
use tauri::{plugin::PluginApi, AppHandle, Runtime};
// 引入 PhantomData，用于持有未使用的泛型参数 R
// 使用 fn() -> R 形式，因为函数指针天然是 Send + Sync 的
use std::marker::PhantomData;

/// 初始化桌面端插件实现
/// 桌面端不需要实际功能，因此返回空实现
pub fn init<R: Runtime, C: DeserializeOwned>(
    // 应用句柄，当前未使用
    _app: &AppHandle<R>,
    // 插件 API，当前未使用
    _api: PluginApi<R, C>,
) -> crate::Result<NotificationSettings<R>> {
    // 返回空的桌面端实现，PhantomData 仅用于告诉编译器此结构体"关联"了泛型 R
    Ok(NotificationSettings { _marker: PhantomData })
}

/// 桌面端 API 访问句柄（空实现）
/// 添加泛型参数 R 以与 mobile 端保持接口一致，避免 lib.rs 中编译失败
/// 使用 PhantomData<fn() -> R> 而非 PhantomData<R>，因为函数指针类型
/// 天然满足 Send + Sync + 'static，无需对 R 额外添加线程安全约束
pub struct NotificationSettings<R: Runtime> {
    // PhantomData<fn() -> R> 是零大小类型，仅用于关联泛型 R
    // fn() -> R 是函数指针类型，编译器始终视其为 Send + Sync
    _marker: PhantomData<fn() -> R>,
}

// 为桌面端 NotificationSettings 实现业务方法
impl<R: Runtime> NotificationSettings<R> {
    /// 桌面端打开通知设置页面
    /// 由于桌面端无此概念，直接返回不支持平台的错误
    pub fn open_notification_settings(&self) -> crate::Result<()> {
        // 返回自定义错误：不支持当前平台
        Err(crate::Error::UnsupportedPlatform)
    }
}
~~~

#### lib.rs（插件主入口）

作用：插件入口文件，重要

~~~rust
// 公开 commands 模块，使其中的命令函数可被 Tauri 宏引用
pub mod commands;
// 公开 models 模块，使数据结构可被外部使用
pub mod models;

// 仅在桌面平台编译时包含 desktop 模块
#[cfg(desktop)]
mod desktop;
// 仅在移动平台（Android/iOS）编译时包含 mobile 模块
#[cfg(mobile)]
mod mobile;

// 引入 Tauri 插件构建器和应用管理器
use tauri::plugin::Builder;
// 引入 Manager trait（提供 state 方法）和 Runtime 泛型
use tauri::{Manager, Runtime};

// 根据编译目标条件引入对应的 NotificationSettings 类型
#[cfg(desktop)]
use desktop::NotificationSettings;
#[cfg(mobile)]
use mobile::NotificationSettings;

// 引入 serde 的序列化相关 trait，用于手动实现 Error 的序列化
use serde::{Serialize, Serializer};

/// 自定义错误枚举类型
#[derive(Debug, thiserror::Error)]
pub enum Error {
    // 平台不支持错误，带有描述信息
    #[error("Unsupported platform")]
    UnsupportedPlatform,
    // 透明包装 Tauri 内部错误，自动实现 From 转换
    #[error(transparent)]
    Tauri(#[from] tauri::Error),
    // 移动端插件调用错误（仅移动平台编译时包含）
    // 必须包含此变体，否则 run_mobile_plugin 返回的 PluginInvokeError
    // 无法通过 map_err(Into::into) 自动转换
    #[cfg(mobile)]
    #[error(transparent)]
    PluginInvoke(
        #[from]
        tauri::plugin::mobile::PluginInvokeError,
    ),
}

// 手动为 Error 实现 Serialize
// Tauri v2 要求命令返回的错误类型必须能序列化为 JSON 才能传递给前端
impl Serialize for Error {
    fn serialize<S>(&self, serializer: S) -> std::result::Result<S::Ok, S::Error>
    where
        S: Serializer,
    {
        // 将错误序列化为简单字符串，前端收到形如 "Unsupported platform" 的文本
        serializer.serialize_str(&self.to_string())
    }
}

// 定义本 crate 的 Result 类型别名为标准 Result，错误类型为自定义 Error
pub type Result<T> = std::result::Result<T, Error>;

/// 为 AppHandle/App/Window 扩展 notification_settings() 方法的 trait
pub trait NotificationSettingsExt<R: Runtime> {
    // 获取 NotificationSettings 实例的引用
    fn notification_settings(&self) -> &NotificationSettings<R>;
}

// 为所有实现了 Manager<R> 的类型实现该 trait
// 这包括 AppHandle、App、Window 等
impl<R: Runtime, T: Manager<R>> NotificationSettingsExt<R> for T {
    // 从 Tauri 状态管理中获取 NotificationSettings 实例
    fn notification_settings(&self) -> &NotificationSettings<R> {
        // state() 从 Tauri 托管状态中取出值
        // inner() 获取内部引用
        self.state::<NotificationSettings<R>>().inner()
    }
}

/// 插件初始化函数
/// 返回配置好的 TauriPlugin，供应用注册使用
pub fn init<R: Runtime>() -> tauri::plugin::TauriPlugin<R> {
    // 使用 Builder 构造插件,"app-setting"，一般为插件名称，用于前端调用时的|前端的内容
    Builder::new("app-setting")
        // 注册前端可调用的命令处理器
        .invoke_handler(tauri::generate_handler![
            // 注册打开通知设置的命令，open_notification_settings，用于前端调用时|后面的内容
            commands::open_notification_settings,
        ])
        // setup 在插件加载时执行，用于初始化状态
        .setup(|app, api| {
            // 根据编译目标初始化对应平台的实现
            #[cfg(mobile)]
            let notification_settings = mobile::init(app, api)?;
            #[cfg(desktop)]
            let notification_settings = desktop::init(app, api)?;
            // 将初始化后的实例注册到 Tauri 状态管理中
            // 这样后续可通过 app.notification_settings() 获取
            app.manage(notification_settings);
            // 返回 Ok 表示 setup 成功
            Ok(())
        })
        // 构建并返回插件实例
        .build()
}
~~~

### permissions文件夹（插件权限）

作用：插件的权限定义

#### default.toml（权限定义）

~~~toml
[default]
description = "插件的默认权限"
permissions = ["allow-open-notification-settings"]
~~~

permissions数组中的元素为插件权限名称，如果插件项目是直接创建的，则该文件中的权限名称需要自己配置，权限名称的组成：`all-` + build.rs中的定义命令。如`allow-open-notification-settings`权限名称中的`open-notification-settings`来源于build.rs中的命令列表中的元素，注意，build.rs中的命令名称如果用下划线组成，则最终组成的权限名称必须改为`-`符号连接

build.rs

~~~rust
// 定义本插件支持的所有命令名称列表
// 这些名称将用于自动生成权限文件和前端类型定义
const COMMANDS: &[&str] = &["open_notification_settings"];

/// 构建脚本主函数，在编译时执行
fn main() {
    // 使用 tauri_plugin 构建器生成插件元数据
    tauri_plugin::Builder::new(COMMANDS)
        // 指定 Android 原生代码的相对路径
        .android_path("android")
        // 指定 iOS 原生代码的相对路径（即使无 iOS 实现也保留）
        .ios_path("ios")
        // 执行构建，生成权限定义等文件
        .build();
}
~~~

如果插件项目是在tauri应用项目中创建的，则只需运行tauri项目（测试或打包都行），会自动根据build.rs中的名称列表自动生成权限，完全不需要手动配置

### android文件夹（安卓源码）

安卓工程项目所在的文件夹

#### android/src/main/java文件夹

##### 插件名称Plugin.kt

文件名称一般为插件的名称+Plugin，且使用大驼峰命名法命名，比如插件名称为`tauri-plugin-app-setting`，则该文件名为AppSettingPlugin

作用：定义插件类，实现插件的具体功能

~~~kotlin
// 包名必须与 build.gradle.kts 中的 namespace 一致，一般为插件名称，如果名称是多个单词组成，则使用下划线连接
package com.plugin.app_setting

import android.app.Activity
import android.content.Intent
import android.os.Build
import android.provider.Settings
import app.tauri.annotation.Command
import app.tauri.annotation.TauriPlugin
import app.tauri.plugin.Invoke
import app.tauri.plugin.Plugin

@TauriPlugin
class AppSettingPlugin(private val activity: Activity) : Plugin(activity) {

    /**
     * 打开当前应用的通知设置页面
     * 仅支持 Android 8.0+ (API 26+)
     */
    @Command
    fun openNotificationSettings(invoke: Invoke) {
        val intent = Intent().apply {
            action = Settings.ACTION_APP_NOTIFICATION_SETTINGS
            putExtra(Settings.EXTRA_APP_PACKAGE, activity.packageName)
        }

        if (intent.resolveActivity(activity.packageManager) != null) {
            activity.startActivity(intent)
            // 返回数据
            invoke.resolve()
        } else {
            // 返回错误信息
            invoke.reject("无法打开通知设置页面")
        }
    }
}
~~~

#### 发布（可选）

先确认Cargo.toml中的name属性的名称在cartes.io中是否能被搜到，防止名称被占用

#### 发布（可选）

先确认`package.json`中的name属性的名称在npmjs中是否能被搜到，防止名称被占用

以下需要执行的命令都在插件项目根目录

1.前往`https://www.npmjs.com/`注册一个账号

2.在登录完成的页面右上角的Account中的Access Tokens中生成一个Token，并复制该Token，并保存好，因为下一次打开不会再显示。

完整填写：

~~~text
Token name	Token名称，自定义
Description	描述，选填
Bypass two-factor authentication (2FA)	绕过2FA认证，必须勾上
Packages and scopes中的Permissions	该Token的功能，选择Read and write (publish and stage)，发布包
Packages and scopes中的Select packages	选择All packages
Expiration Date	Token有效期，随便选
~~~

3.写入token

方式一，全局写入：该命令会将token写入你的全局~/.npmrc文件，token不会被回显，也不会进入任何项目仓库，发布时也不会带上，可以放心：

~~~cmd
npm config set //registry.npmjs.org/:_authToken=你复制的token
~~~

方式二，项目及写入，如果只想为特定项目配置token，可以在项目根目录创建.npmc文件，写入以下内容，同样也不会发布时带上，可以放心：

~~~txt
//registry.npmjs.org/:_authToken=你的复制的token
~~~

4.token配置验证：

~~~cmd
npm whoami
~~~

如果输出的是你复制的token所在的账号，则表示配置成功

5.预览发布的内容：

~~~cmd
npm pack --dry-run
~~~

这会列出将要打包上传的所有文件，检查一下有没有不该出现的敏感文件

6.发布：

~~~cmd
npm publish
~~~

看到类似下面的输出就说明成功了：

~~~cmd
npm notice Publishing to https://registry.npmjs.org/
+ my-npm-package@1.0.0
~~~

7.发布成功后验证：

~~~cmd
npm info 你的包名
npm view 你的包名 versions
~~~

如果输出包的相关信息，则表示成功，可以在npmjs中搜索到

警告：

+ npm logout命令一般不要执行，它会永久删除本地和npm账户中的token

## 使用插件

1.tauri项目的Cargo.toml添加插件包：

~~~toml
[dependencies]
插件名称 = {path="插件项目所在的相对或绝对路径"}
插件名称 = "版本号" # 如果已经发布
~~~

2.lib.rs中注册插件：

~~~lib.rs
#[cfg_attr(mobile, tauri::mobile_entry_point)]
pub fn run() {
    tauri::Builder::default()
        .plugin(tauri_plugin_app_setting::init()) # 注册插件
        .plugin(tauri_plugin_opener::init())
        .invoke_handler(tauri::generate_handler![])
        .run(tauri::generate_context!())
        .expect("error while running tauri application");
}
~~~

3.default.json添加权限：

~~~json
{
  "$schema": "../gen/schemas/desktop-schema.json",
  "identifier": "default",
  "description": "Capability for the main window",
  "windows": ["main"],
  "permissions": [
    "app-setting:default" 默认权限，app-setting是插件名称的后缀
     插件的其它自定义权限
  ]
}
~~~

4.前端中使用

如果插件已生成前端依赖，则可以添加依赖

~~~txt
# npm install 插件打包好的tgz格式文件的绝对路径
npm install D:\TauriProject\tauri-plugin-lingyi-toolbox\tauri-plugin-lingyi-toolbox-0.1.0.tgz
# 如果已发布
npm install 依赖名
~~~

前端调用：

~~~javascript
import {openNotificationSettings} from "@tauri/plugin-app-setting"
await openNotificationSettings()
~~~

如果没有生成依赖，则可以在前端中直接调用rust命令的方式调用功能：

~~~javascript
import { invoke } from '@tauri-apps/api/core'
// app-setting：插件名称后缀，open_notification_settings：插件build.rs中定义的命令，执行对应的插件功能
await invoke('plugin:app-setting|open_notification_settings')
~~~

## 插件的输入\输出参数的完整定义

从输入（前端→Kotlin）和输出（Kotlin→前端）两个方向，每种情况从TS→Rust→Kotlin全链路。

### 输入参数

无论那种输入类型，全链路都是固定的：

~~~text
index.ts：组装 payload 对象 { url, packageName }
    ↓
commands.rs：接收 payload 结构体（OpenBrowserRequest），整包传给 mobile 层
    ↓
mobile.rs：接收 payload，run_mobile_plugin("openBrowser", payload) 原样发出去
    ↓
Kotlin：从 invoke.getArgs() 逐字段读取（optString("url")、optString("packageName")）
~~~

唯一变化的就是：

1. models.rs 里的类型（String / Option<T> / Vec<T> / 嵌套 struct）
2. Kotlin 里读值的 API（optString / optInt / optJSONArray / optJSONObject）
3. TS 里的类型标注（string / string? / T[] / 嵌套 interface）
4. 其余文件（commands.rs、mobile.rs）结构完全一样，只是字段名和类型跟着 models.rs 变。

#### 无参数

Kotlin：

~~~kotlin
@Command
fun doSomething(invoke: Invoke) {
    // 不读 invoke.getArgs()
    invoke.resolve()
}
~~~

models.rs：

~~~rust
// 需要一个空结构体占位（Tauri 命令签名要求有参数）
#[derive(Debug, Deserialize, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct DoSomethingRequest {}
~~~

commands.rs：

~~~rust
#[tauri::command]
pub(crate) async fn do_something<R: Runtime>(
    app: AppHandle<R>,
    payload: DoSomethingRequest,
) -> Result<()> {
    app.app_setting().do_something(payload)?;
    Ok(())
}
~~~

mobile.rs：

~~~rust
pub fn do_something(&self, payload: DoSomethingRequest) -> crate::Result<()> {
    self.0
        .run_mobile_plugin("doSomething", payload)
        .map_err(Into::into)
}
~~~

desktop.rs：

~~~rust
pub fn do_something(&self, _payload: DoSomethingRequest) -> crate::Result<()> {
    Err(crate::Error::UnsupportedPlatform)
}
~~~

index.ts：

~~~typescript
export function doSomething(): Promise<void> {
  return invoke('plugin:app-setting|do_something', { payload: {} });
}
~~~

#### 无返回

kotlin：

~~~kotlin
@Command
fun xx(invoke: Invoke) {
    try {
        // ...业务逻辑
        // 无数据返回：resolve 不传任何参数
        // Tauri 会把这次调用标记为「成功但无返回值」
        invoke.resolve()
    } catch (e: Exception) {
        // 失败：reject 传错误字符串，前端会走到 catch
        invoke.reject("失败: ${e.message}")
    }
}
~~~

models.rs：

~~~rust
// 只需要 Request（如果命令无入参，结构体留空即可）
#[derive(Debug, Deserialize, Serialize)]
#[serde(rename_all = "camelCase")]
pub struct XxRequest {}

// ❌ 关键：无数据返回时，不要定义 XxResponse
//    否则会造出「永远 success: true」的冗余字段
~~~

commands.rs：

~~~rust
#[tauri::command]
pub(crate) async fn xx<R: Runtime>(
~~~

三条铁律：

1. commands.rs 和 mobile.rs 只透传，payload 整包往下走，不拆字段。

2. `#[serde(rename_all = "camelCase")]` 是命名桥接的唯一开关，漏写必报 missing field。

3. 无数据返回就用 Result<()>，不要造 { success: true }，那是冗余字段。
